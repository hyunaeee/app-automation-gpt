# Launchpad · AI Development Agent

짧은 자연어 아이디어를 **요구사항 → 기능 → 구조 → 코드 → 검증 → 수정 → 실행 가능한 프로젝트**로 연결하는 개발 워크스페이스입니다. 로컬 실행과 Vercel 배포 구성을 함께 제공합니다. 비개발자가 상세 설문에 응답하지 않아도 기본값으로 작업을 시작하고, 에이전트가 선택한 가정과 실제 생성 파일·검증 결과를 확인할 수 있습니다.

다른 Codex에서 개발을 이어갈 때는 저장소를 clone한 폴더를 열고 [개발 인계 문서](CODEX_HANDOFF.md)를 먼저 읽어 주세요. 전체 플랫폼과 앱 샘플, 검증 결과, 실행 방법, 남은 작업을 구분해 기록했습니다. 개인 키·로그인 정보와 로컬 프로젝트 데이터는 Git에 포함하지 않습니다.

## Vercel 배포

Vercel에서 프런트엔드와 제어 API를 제공하고, 장시간 작업 및 생성 앱 실행은 **Vercel Sandbox**, 프로젝트 상태와 소스 보관은 **비공개 Vercel Blob**으로 분리합니다. Functions의 임시 파일 시스템이나 요청 종료 후 백그라운드 작업에 의존하지 않습니다.

1. 이 저장소를 Vercel 프로젝트로 가져옵니다. 빌드 명령 `npm run build`, 결과 디렉터리 `dist`를 사용합니다.
2. 프로젝트에 **Private Blob** 저장소를 연결해 `BLOB_READ_WRITE_TOKEN`을 설정합니다.
3. `SESSION_SECRET`(무작위 32자 이상)과 Google OAuth 설정을 등록합니다. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `PUBLIC_APP_URL`이 필요하며 [Google 로그인 문서](docs/google-login.md)에 리디렉션 설정이 있습니다. Google을 사용하지 않으면 `WORKSPACE_PASSWORD`(12자 이상)로 보호합니다.
4. 각 사용자는 **설정 → 나의 AI 연결**에서 개인 OpenAI API 키와 모델을 연결할 수 있습니다. 공용 키를 제공하면 사용자는 Google 로그인만 한 뒤 생성을 시작할 수 있으며 모델 사용료는 공용 API 계정에 청구됩니다.
5. Sandbox 접근 권한과 OIDC 설정을 확인하고 배포합니다.

키와 비밀번호에 `VITE_` 접두사를 붙이지 마세요. Vercel의 설정 화면에서 서버 환경 변수로 관리합니다. Google 로그인은 신원 확인용이며 Google AI 구독 크레딧을 자동으로 연결하지 않습니다.

구체적인 설정, 미리보기 수명, 실패 복구 및 제한은 [Vercel 배포 문서](docs/vercel.md)를 참고하세요. **실제 OpenAI 호출과 Vercel 배포 검증에는 해당 서비스의 자격 증명이 필요합니다.** 로컬 통합 테스트와 공급자·클라우드 저장소 테스트는 키 없이 실행됩니다.

## 빠른 실행

Node.js 22 이상이 필요합니다.

```sh
npm install
npm run dev
```

[개발 화면 열기](http://127.0.0.1:5173) · 백엔드 `http://127.0.0.1:3001`

```sh
npm run build
npm start
```

빌드 후에는 [http://127.0.0.1:3001](http://127.0.0.1:3001)에서 프런트엔드와 API를 함께 제공합니다.

## 사용 흐름

1. 웹 앱, Android 모바일 앱, AI 에이전트를 선택하고 만들고 싶은 것을 입력합니다. 에이전트는 웹 화면, HTTP API, 로컬 MCP 서버 중 결과물 방식을 선택합니다. 기획·결과물 샘플로 시작할 수도 있습니다.
2. 초기 예상 비용·시간을 확인하고 생성합니다. 단가가 없으면 비용을 미산정으로 표시합니다. 추가 질문 없이 기본 기능과 가정을 정리하고 8단계 워크플로를 실행합니다.
3. 프로젝트 화면에서 기능 명세, 파일, 단계별 로그, 검증 결과를 확인합니다.
4. 웹 앱은 미리보기를 열어 회원가입하고, 모바일 앱은 기기 프레임에서 바로 사용합니다. 모바일 앱은 오프라인 프로필·로컬 저장 방식입니다.
5. 소스 ZIP을 내려받아 독립 실행합니다. 모바일은 준비된 SDK 실행기에서 실제 개발용 APK를 자동 빌드하고 다운로드합니다.
6. 결과물 아래에서 바꾸고 싶은 내용을 입력하면 기존 화면 코드를 바탕으로 새 버전을 생성합니다. 원본은 보존되고 사용자 데이터는 새 버전으로 이전되지 않습니다. AI 미연결 시에는 맞춤 수정 없이 템플릿 사본만 만듭니다.

로컬 프로젝트와 생성 파일은 `.data/`에, Vercel 배포의 프로젝트 상태와 소스는 비공개 Blob에 보존합니다. 새로고침 후에도 진행 결과를 다시 열 수 있습니다. 실행 중인 작업을 취소하거나 실패한 작업을 재시도할 수 있습니다.

## 로컬 모드와 AI 모드

| 모드 | 동작 | 용도 |
| --- | --- | --- |
| 로컬 템플릿 | 입력 키워드와 프로젝트 유형을 바탕으로 미리 정의한 기능과 템플릿을 조합합니다. 실제 파일을 생성하고 실제 서버를 검증합니다. | 키 없이 설치·워크플로·로그인·데이터 저장 검증 |
| OpenAI API | 개인 또는 공용 OpenAI 키로 계획·코드 생성·오류 수정을 수행합니다. | 로컬 및 Vercel의 AI 프로젝트 생성 |
| 로컬 Codex 구독 | 설치된 공식 Codex CLI의 ChatGPT 로그인으로 계획·코드 생성·오류 수정을 수행합니다. | 개인 컴퓨터에서 구독 한도를 사용하는 생성·테스트 |

로컬 모드는 범용 자연어 코드 생성 모델이 아닙니다. 화면에서 현재 모드를 표시합니다. 로컬 에이전트의 텍스트 처리 또한 규칙 기반 도구이며, 추론 모델 응답으로 표시하지 않습니다.

AI 생성을 활성화하려면 사이트의 **설정 → 나의 AI 연결**에서 개인 키와 계정에서 사용할 수 있는 모델 ID를 입력합니다. 연결 확인을 위한 유료 호출은 하지 않으며, 키·모델 권한은 첫 생성 요청에서 검증합니다. 공용 서버 키를 제공하려는 경우에는 `.env.example`을 `.env`로 복사하고 다음 값을 설정한 뒤 서버를 다시 시작합니다.

```dotenv
OPENAI_API_KEY=your-api-key
OPENAI_MODEL=gpt-4.1-mini
PORT=3001
HOST=127.0.0.1
```

개인 API 키는 브라우저의 localStorage·쿠키에 저장하거나 소스 ZIP에 포함하지 않습니다. 서버에서 AES-256-GCM으로 암호화해 로컬 `.data/credentials/` 또는 private Blob에 보관하고 12시간 후 사용을 만료합니다. 브라우저에는 서명된 HttpOnly 식별 쿠키만 남습니다. Google 로그인 사용 시 프로젝트와 개인 키는 검증된 Google 계정에 귀속되어 같은 계정으로 다른 브라우저에서도 조회할 수 있습니다. Google 미설정 환경에서는 서명된 브라우저 쿠키에 귀속되며 쿠키 삭제 후 복구는 지원하지 않습니다. 키를 교체·해제하면 해당 키의 생성 작업과 미리보기가 종료됩니다. 만료된 키로 생성한 프로젝트의 AI 실행은 키 재연결이 필요하며 공용 키로 자동 대체하지 않습니다.

실제 OpenAI 요청에는 해당 API 계정의 사용 요금이 발생합니다. 공용 서버 키를 설정했다면 개인 키가 없는 사용자의 새 프로젝트에는 공용 키가 사용되며 화면에 표시합니다. 모델 연동은 [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)와 [구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 기준으로 구현합니다.

### ChatGPT 구독으로 로컬 생성

이 컴퓨터의 공식 Codex CLI에서 `codex login`으로 ChatGPT에 로그인하고 `codex login status`를 확인합니다. `.env`에 `AI_PROVIDER=codex`를 설정한 뒤 서버를 다시 시작하면 로컬 구독 실행을 사용합니다. `CODEX_CLI_PATH`는 실행 파일을 PATH에서 찾지 못할 때, `CODEX_MODEL`은 특정 모델을 명시하려는 경우에만 지정합니다. 기본 모델 ID를 코드가 강제로 선택하지 않습니다.

구독으로 테스트할 때는 사이트에 연결된 개인 API 키를 해제하고 화면의 **Codex 구독** 표시를 확인하세요. 개인 API 연결이 있으면 그 연결이 우선합니다. Codex 자식 프로세스에는 API 키를 전달하지 않으며, 구독 실패를 공용 API 키로 자동 대체하지 않습니다. 생성된 앱의 `ai` 도구를 실제로 사용할 때 필요한 OpenAI API 키는 별도입니다. [로컬 구독 설정과 제한](docs/openai-subscription.md)

Vercel에는 이 컴퓨터의 Codex 로그인 정보가 전달되지 않습니다. 원격 앱에서 사용자별 구독 사용량을 지원하는 Sign in with ChatGPT는 별도의 통합이며 현재 연결하지 않았습니다. 공식 문서는 오픈소스·로컬 앱의 공개 흐름과 원격·유료 앱의 별도 접근 신청을 구분합니다. [공식 OpenAI 문서](https://developers.openai.com/siwc/token-sharing-open-source)

### AI 에이전트 결과물

| 방식 | 실행·연결 |
| --- | --- |
| 웹 앱 | 생성 앱의 웹 화면에서 가입·로그인 후 도구 사용 |
| HTTP API | `/console`에서 프로젝트 전용 토큰을 발급하고 `POST /v1/agent/run` 호출. `openapi.json` 포함 |
| MCP 서버 | ZIP의 의존성을 설치하고 `mcp.config.json`의 절대 경로를 지정해 MCP 클라이언트에 로컬 stdio 서버로 등록 |

MCP의 웹 미리보기 주소는 원격 MCP URL이 아닙니다. 각 결과물의 README에 연결 방법과 키 설정이 포함됩니다. 출력 방식은 새 버전 생성과 재시도에도 유지됩니다.

### 패션·가방 설계 샘플

가방·의류의 도면과 재료 견적을 요청하는 웹 앱에는 검증된 전용 템플릿을 사용합니다. 사용자가 확인한 치수를 바탕으로 도식, 원단 배치·구매 수량, 입력 단가에 따른 예상 비용을 계산하고 기기에 초안을 저장합니다. AI는 기능 명세와 CSS 디자인 개선을 담당하며, 기존 계산 JavaScript와 HTML은 보존합니다. 이 샘플에서 자연어 수정은 디자인 스타일 개선 범위이며, 치수·수량·단가는 앱의 입력 폼에서 변경합니다.

이 템플릿은 임의의 백엔드 기능, 사진·설명만으로 얻는 실측치, 바로 재단 가능한 봉제 패턴이나 실시간 업체 견적을 생성하지 않습니다. 제작처 링크는 검색으로 연결되며 문의를 대신 전송하지 않습니다.

## 모바일·디자인·스토어 확장

- [Android 빌드](docs/android-build.md): 실제 SDK 컴파일과 개발 서명 APK. Vercel에서는 SDK를 준비한 별도 실행기 URL·토큰을 연결해야 합니다. 로컬 빌드와 에뮬레이터 실행은 검증했으며, 원격 배포 환경은 자격 증명을 연결한 뒤 확인해야 합니다.
- [디자인 서비스와 견적](docs/design-integrations.md): Stitch·v0·Figma 연결 후보, 서비스별 인증과 초기 비용 추정. 외부 디자인 서비스는 아직 연결하지 않았습니다. 견적은 규칙 기반 예상 범위이며 예산 상한을 강제하지 않습니다.
- [스토어 배포 설계](docs/store-publishing.md): AAB/릴리스 서명, 사용자별 개발자 계정, iOS 빌드 실행기, 심사 상태 관리. 현재 스토어 자동 업로드·심사 제출은 구현하지 않았습니다.
- [OpenAI 구독 실행](docs/openai-subscription.md): 로컬 Codex 구독 실행과 Vercel API 방식의 구분. 현재 활성 AI 제공자는 OpenAI이며 Google 로그인은 계정 식별에 사용합니다.

## 코드 구조

```text
src/                 React 워크스페이스와 프로젝트 상세 UI
server/              API, 저장소, 워크플로, 에이전트, 생성 템플릿
server/cloud/        Vercel 인증·Blob 저장·Sandbox 실행 어댑터
api/                 Vercel Function 진입점
tests/               실제 API·생성 서버를 사용하는 통합 테스트
e2e/                 브라우저에서 프로젝트 생성 및 모바일 UI 검사
docs/architecture.md 단계별 책임, 데이터 계약, 확장 지점
scripts/dev.mjs      프런트엔드와 백엔드 개발 서버 실행
.data/               프로젝트 메타데이터와 생성 파일 (Git 제외)
```

프런트엔드: React · TypeScript · Vite · Lucide. 컨트롤러: Node.js · Express. 생성 웹 앱과 API 서버는 Node.js와 브라우저 HTML/CSS/JavaScript를 사용하며, MCP 연결에는 생성 프로젝트에 지정한 MCP SDK 의존성을 설치합니다. 로그인 비밀번호는 scrypt로 해시하고 세션 쿠키로 인증합니다. 기본 저장소는 파일 기반 JSON이며 사용자별 데이터를 분리합니다.

독립적인 Planner, Coding, Validation, Debugging 단계를 워크플로가 연결합니다. 새로운 프로젝트 유형과 도구를 추가하는 방법 및 운영 환경 확장은 [구조 문서](docs/architecture.md)를 참고하세요.

## 검증

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

통합 테스트는 임시 프로젝트를 생성하고 실제 자식 서버에서 회원가입, 로그인, 로그아웃, 데이터 저장·소유권 분리, 에이전트 실행, ZIP 출력을 검증합니다. 외부 API 키 없이 실행할 수 있습니다.

## MVP 범위

로컬에서는 개인용 워크스페이스, Vercel에서는 Google 계정 또는 공용 비밀번호로 보호하는 크루용 워크스페이스를 제공합니다. 생성 앱의 회원 계정과 워크스페이스 접근 제어는 서로 다른 영역입니다. 공개 SaaS 서비스용 다중 조직·과금·생성 앱의 운영 배포 자동화는 포함하지 않습니다.

모델이 작성한 서버 코드나 셸 명령을 호스트에서 임의로 실행하지 않습니다. MVP는 검증된 서버 템플릿과 허용된 브라우저 파일을 결합하며, Vercel에서는 별도 Sandbox에서 실행합니다. 따라서 임의의 언어·프레임워크·외부 서비스가 필요한 프로젝트까지 자동 완성하는 시스템은 아닙니다. 공개 서비스로 확장할 때는 영속 DB, 사용자별 권한·사용량 제한과 비밀 관리 등을 추가해야 합니다.

생성 결과의 기본 검증은 문법과 핵심 인증·데이터 흐름을 확인합니다. 모든 도메인 기능의 정확성이나 운영 보안 검토를 대신하지 않습니다. API 장애·실행 오류는 실패 상태와 로그에 남기며 완료로 위장하지 않습니다.

브라우저 테스트 중 실제 APK 다운로드 검사는 Android SDK/JDK가 준비된 로컬 서버를 사용합니다. 키 없는 테스트에서는 모델 공급자를 모의 검증하며, 실제 유료 모델 생성 성공을 뜻하지 않습니다.
